# Аналитика и прогнозирование тарифов грузоперевозок  

## Запуск

На машине с Docker и Compose:

```bash
docker-compose up
```

Запуск pipeline создаёт схемы core/mart, загружает 300 000
исходных сделок, выполняет ETL, обучает модель и пишет прогнозы.

## Вопрос 1 — ETL и Data Quality

Пайплайн читает окно дат (--start-date/--end-date) из raw.prices,
валидирует и очищает, конвертирует валюту, обогащает категории и идемпотентно загружает в core.prices.

### Правила карантина (core.dq_quarantine_prices, причина reason_code):

| Правило                                        | reason_code                                   | 
|:-----------------------------------------------|:----------------------------------------------| 
| price <= 0                                     | INVALID_PRICE                                 | 
| RUB и price <= 1000                            | RUB_PRICE_UNDER_MIN_THRESHOLD                 | 
| distance <= 0                                  | INVALID_DISTANCE                              | 
| total_weight < 0                               | INVALID_WEIGHT                                | 
| total_volume < 0                               | INVALID_VOLUME                                | 
| город отсутствует в raw.cities                 | UNKNOWN_DEPARTURE_POINT / UNKNOWN_DESTINATION | 
| USD/EUR без точного курса по nearest_rate_date | MISSING_FX_RATE                               | 


Результаты (300 000 записей источника):

Идемпотентность: INSERT … ON CONFLICT (price_id) DO UPDATE (core)
и ON CONFLICT (price_id, reason_code) DO NOTHING (карантин);
повторный прогон того же окна не задваивает строки (проверено автотестами).


## Вопрос 2 — DWH и аналитические витрины
Устранены структурные аномалии измерений:

Дедупликация городов (core.dim_city): gc_id не уникален — берётся строка с минимальным cities.id
(42 → 40 городов).

Унификация кузовов (core.price_body_type):
price_body_types → body_types.std_id → бизнес-группа,
с фолбэком на prices.body_type и Не указан; без дублей одной сделки внутри одной группы.


## Вопрос 3 — ML и результат

Дата снимка фиксирована: **2026-10-26**, независимо от даты запуска.

| Выборка | Окно по `loading_date`     |  Сделок |
|---------|----------------------------|--------:|
| Train   | `[2026-07-26, 2026-10-05)` |  24 226 |
| Test    | `[2026-10-05, 2026-10-26]` |  12 808 |
| Future  | после 2026-10-26           |   5 820 |

Защита от утечек: исключены производные таргета
(`price_with_vat`, `price/distance`, `price/weight`), агрегаты `price_group_stats`,
а `outlier_mark` используется только для очистки таргета, не как признак.

Признаки заданы явным списком: отдельные города, регионы отправления и назначения,
координаты, расстояние, вес, объём, категории и кузов. Добавлены год, месяц,
день недели и день года, sin/cos для периодов 12, 7 и 365,25. Для сделки
с несколькими группами кузовов используется отсортированный набор групп
как одна категория: сделка не дублируется в обучении и метриках.

Результат:

| Метрика на test |                Значение |
|-----------------|------------------------:|
| R²              |                0.918139 |
| MAPE            |                15.65141 |
| RMSE            |          54 735,16 руб. |
| MAE             |          28 393,67 руб. |

Параметры, признаки, границы и метрики
сохраняются в `mart.ml_model_runs`; идентификатор модели включает хеш обучающих
данных и параметров.
Прогнозы данного `as_of` заменяются атомарно вместе
с метриками.
Повтор не меняет численные результаты; время расчёта обновляется.

## Проверка

```bash
docker compose run --rm pipeline python -m pytest -q -p no:cacheprovider
docker compose exec postgres psql -U logistics -d logistics
```

Тесты покрывают правила DQ и категории,
отсутствие таргет-утечек в признаках,
границы time-split, корректность циклического кодирования,
идемпотентность (отсутствие дублей в core.prices, mart.ml_price_predictions)
и NULL-ошибки для будущих заявок. 16 тестов, они используют отдельную временную БД и удаляют её
после выполнения.

## Ограничения источника

1. `outlier_mark` на 2026-10-26: самые свежие сделки за день снимка ещё не прошли ночной джоб
разметки и имеют `outlier_mark=false` по умолчанию — это ограничение исходных данных
(зафиксировано в задании), не гарантирует отсутствия выброса. Флаг сохраняется как есть;
его пересчёт и подбор фильтров по test не выполняются.
2. loading_city = unloading_city: не отбраковывается
3. Партиционирование core.prices/raw.price_dates не сделано: на 300 тыс. сделок не требуется,
при росте до миллионов — следующий шаг.
